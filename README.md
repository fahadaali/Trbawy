# منصة المجلس التربوي

منصة داخلية مغلقة لإدارة **محاضر الاجتماعات** و**التقييمات التربوية** لثلاثة مجالس تربوية،
مبنية بالكامل على بنية Cloudflare (Workers + D1 + R2) وبواجهة عربية RTL.

> الإصدار الحالي ينفّذ المراحل حسب خطة البناء في وثيقة المتطلبات. راجع قسم **حالة البناء** أدناه.

---

## البنية التقنية

| المكوّن | التقنية |
|---|---|
| الواجهة (SPA عربية RTL) | أصول ثابتة تُقدَّم عبر Cloudflare Workers Assets |
| الخدمات الخلفية | Cloudflare Workers + [Hono](https://hono.dev) |
| قاعدة البيانات | Cloudflare D1 (SQLite) |
| تخزين الملفات | Cloudflare R2 |
| المهام المجدولة | Cron Triggers |
| البريد | خدمة خارجية (Resend / MailChannels) — تُضاف في مرحلة الإشعارات |

الكود بلا خطوة بناء معقّدة: `wrangler` يجمّع TypeScript مباشرة، والواجهة HTML/CSS/JS صرف.

---

## التشغيل محلياً

```bash
npm install

# أنشئ قاعدة D1 وضع المعرّف في wrangler.toml مكان PLACEHOLDER_DATABASE_ID
npx wrangler d1 create tarbawi-db

# أنشئ حاوية R2
npx wrangler r2 bucket create tarbawi-files

# طبّق المخطط محلياً
npm run db:init
npm run db:seed

# شغّل بيئة التطوير
npm run dev
```

عند أول طلب، تُنشأ تلقائياً المجالس الثلاثة والمستخدمون العشرة والعضويات والبنود الثابتة
وقوالب المعايير عبر `src/lib/bootstrap.ts`.

## النشر على Cloudflare

```bash
# قاعدة جديدة تمامًا فقط — طبّق المخطط والبيانات الأولية مرة واحدة
npm run db:init:remote
npm run db:seed:remote

npm run deploy
```

الربط بـ GitHub: كل دفعة إلى الفرع الرئيسي تُنشر تلقائياً عبر تكامل Cloudflare مع المستودع.
(النشر اليدوي يحتاج `CLOUDFLARE_API_TOKEN` في البيئة أو `npx wrangler login` على جهازك.)

**الترقية لا تحتاج خطوة قاعدة بيانات:** عند أول طلب بعد النشر تُنشئ المنصة الجداول
والأعمدة الناقصة ذاتيًا وتُعبّئ ما يلزم بأثر رجعي (`ensureBootstrap`)، فلا تُشغَّل
`db:init:remote` على قاعدة عاملة. وكذلك مفاتيح إشعارات الدفع تُولَّد وتُحفظ تلقائيًا
ما لم تُضبط كأسرار بيئة.

## الحسابات الافتراضية (بيئة التجربة)

كلها بكلمة المرور الافتراضية **`1234`** مع **إلزام تغييرها عند أول دخول**.

| الدور | البريد |
|---|---|
| رئيس المجلس التربوي | `president@tarbawi.local` |
| نائب الرئيس | `vice@tarbawi.local` |
| مشرف الثانوي الأول | `sec.super@tarbawi.local` |
| مشرف المتوسط الأول | `mid.super@tarbawi.local` |
| أعضاء الفريق | `sec.m1` `sec.m2` `mid.m1` `mid.m2` `@tarbawi.local` |
| مدير النظام | `admin@tarbawi.local` |

> **ملاحظة أمنية:** كلمة المرور الافتراضية الموحّدة معتمدة كما طُلب في الوثيقة مع إلزام التغيير.
> يمكن لاحقاً التحوّل إلى كلمة عشوائية لكل مستخدم تظهر لمنشئ الحساب مرة واحدة (قرار معلّق رقم ١).

## بنية المشروع

```
migrations/        مخطط قاعدة البيانات (0001_init.sql) والبيانات الأولية
src/
  index.ts         نقطة الدخول، تركيب المسارات، تقديم الواجهة
  types.ts         الأنواع المشتركة
  permissions.ts   مصفوفة الصلاحيات ودرجات الاطلاع (كامل/تاريخي/شخصي)
  lib/             crypto, hijri, audit, bootstrap, userlifecycle (تقرير الأثر ودورة حياة المستخدم)
  middleware/      auth (الجلسات، خمول ٨ ساعات، إلزام تغيير كلمة المرور)
  routes/          auth, users, councils, audit  (+ المزيد لكل مرحلة)
public/            الواجهة العربية RTL (index.html, css, js)
```

### مراجعة الاكتمال والتنظيف

بعد اكتمال المراحل، أُجريت مراجعة تغطية شاملة مقابل الوثيقة، وأُكمِلت الميزات التالية:
- **محرر نصوص عربي RTL متكامل** لبنود المحضر (عناوين، قوائم، جداول، تظليل، صور) مع تنقية HTML
  آمنة على الخادم (قائمة سماح صارمة — تم اختبارها ضد XSS).
- **محضر تصويب/ملحق** مرتبط بالمحضر الأصلي المعتمد، مع روابط متبادلة.
- **تصدير حزمة محاضر** فترة معيّنة لمجلس في ملف واحد.
- **استيراد المعايير** من CSV بمعاينة وتقرير أخطاء.
- **بحث الأرشيف** داخل نص البنود وأسماء الحضور ونص القرارات/المهام.

وتم تنظيف الكود: لا استيرادات أو دوال أو متغيّرات غير مستخدمة (تحقق `tsc --noUnusedLocals
--noUnusedParameters`)، ولا كود ميت، وأدوات CSV والحساب المرجّح مشتركة بلا تكرار.

### تدقيق معمّق ثانٍ (مراجعة مستقلة متعددة المحاور)

أُجري تدقيق شامل ثانٍ عبر مراجعات مستقلة (تغطية المتطلبات، نظافة الكود، الصحّة والأمان)،
وعُولجت كل النتائج المؤكَّدة:

- **أمان:** إغلاق XSS مخزّن (تنقية نص البنود في كل مسارات الكتابة + شبكة أمان في المنقّي)،
  إغلاق تسريب نتائج بين المراحل في النافذة التفصيلية، إغلاق IDOR في `/file` (تضمين التواقيع
  والشعار كـ data URI داخل صفحة الطباعة وحصر `/file` بالهوية البصرية العامة)، والتحقق من أن
  كاتب المحضر عضو في المجلس.
- **صحّة:** إصلاح دالة عرض الأخطاء المفقودة، منع تعديل نص القرار بعد إقفال المحضر، إضافة قيد
  فريد لأرقام القرارات/المهام.
- **تغطية:** إضافة **لوحة قيادة المشرفين وأعضاء الفرق** (القسم ٥٫٦)، وإضافة قناة البريد
  لإشعارَي «إسناد مهمة» و«فتح دورة تقييم»، وإظهار المسؤولين في جدول قرارات المحضر.
- **تنظيف:** حذف تصديرات ميتة، توحيد منطق تقدّم المقيّمين وصلاحية الإنشاء وخرائط الحالة،
  تحويل الاستيرادات الديناميكية إلى استاتيكية، وربط واجهات لنقاط النهاية غير المربوطة.

### تحسينات تجربة تحرير المحاضر

بعد ملاحظات الاستخدام الفعلي، أُعيد تصميم تدفّق التحرير ليتم **في مكانه** بدل النوافذ المتتابعة:

- **تحرير البنود من أسفل المحضر مباشرة:** كل بند في «جدول الأعمال والبنود» صار قابلاً للتحرير في موضعه —
  تعديل العنوان بالكتابة فيه (يُحفظ عند الخروج من الحقل أو بـ Enter)، وزر «إضافة/تعديل المحتوى» يفتح
  المحرر الغني تحت البند نفسه، مع إعادة الترتيب (أسهم أو سحب وإفلات) والحذف وإضافة بند جديد من نفس المكان.
  المحتوى يُحفظ تلقائياً عند الانتقال لبند آخر أو بـ `Ctrl/⌘ + Enter`. نافذة **«تعديل البنود»** في الأعلى
  باقية كما هي للتحرير الجماعي وإعادة الترتيب دفعة واحدة. (نقاط نهاية جديدة: إضافة/تعديل/حذف بند وإعادة ترتيب.)
- **الصياغة بالذكاء الاصطناعي من مربع النص نفسه:** اختفى مربع «النقاط» المنفصل داخل النافذة —
  يكتب المستخدم نقاطه في محرر المحتوى ثم يضغط «صياغة المكتوب» فتُستبدل بنص محضر رسمي، مع زر
  «تراجع عن الصياغة» لاسترجاع ما كتبه.
- **تسجيل صوتي مباشر:** زر «تسجيل صوتي» داخل المحرر (وفي نافذة استخراج القرارات) يسجّل من الميكروفون
  مع عدّاد حي، وعند الإيقاف يُفرَّغ التسجيل نصاً ويُدرَج في المربع — مع بقاء خيار **«ملف صوتي»** لرفع تسجيل محفوظ.
- **مؤقّت الاجتماع وتعديل الوقت وحده:** لوح توقيت في ترويسة المحضر ببدء/إيقاف يلتقط **التوقيت المحلي للجهاز**
  ويعرض عدّاداً حيّاً يستمر بعد إعادة تحميل الصفحة، ويسجّل وقت النهاية والمدة عند الإيقاف. وللإدخال اليدوي
  حقل نصّي متسامح يقبل `٩:٣٠ ص` و`9:30 م` و`0930` و`9`. تعديل الترويسة صار **جزئياً**: يُرسَل الحقل المتغيّر
  وحده فلا يلزم تعبئة بقية الحقول لقبول تغيير الساعة (وتُطبَّع الأوقات على الخادم أيضاً).
- **إضافة سريعة للقرارات والمهام:** سطر واحد أسفل جدول القرارات (نوع + نص + استحقاق + Enter) بدل فتح النافذة،
  مع بقاء «إضافة بتفاصيل كاملة». وفي نافذة التفاصيل: اختصارات تاريخ الاستحقاق (اليوم/٣ أيام/أسبوع/أسبوعان)،
  و«تحديد الحاضرين» للمسؤولين، وتحميل المسؤولين الحاليين عند التعديل (كان تعديل بند يمسحهم).
- **تحويل بند إلى قرار/توصية/مهمة بضغطة:** زر «↤ إلى مهمة» في كل بند يفتح نموذج البند مهيّأً بعنوان البند
  ونوع «مهمة» وتاريخ استحقاق مقترح، ويُحدَّث جدول القرارات وحده بعد الحفظ بدل إعادة بناء الصفحة
  (فلا يضيع ما يحرّره المستخدم في بقية الصفحة).
- **مسودة محلية لمحتوى البند:** يُحفظ ما يُكتب في المحرر محلياً على الجهاز أثناء الكتابة (بما فيه ناتج
  الصياغة والتفريغ الصوتي). فإن انقطع الاتصال أو أُغلق المتصفح قبل الحفظ، يظهر وسم **«مسودة محلية»**
  على البند وشريط **«استعادتها / تجاهلها»** عند فتحه، وتُرفع المسودات المعلّقة تلقائياً فور عودة الاتصال.
- عرض الأوقات بالعربية (٩:٣٠ ص) في الواجهة وصفحة الطباعة، وحساب مدة الاجتماع تلقائياً.
- المنبثق العائم لـ«العناصر بانتظارك» صار يُغلق بالنقر خارجه وتلقائياً بعد ١٢ ثانية بدل حجب محتوى الصفحة.

### إخراج المحضر وترحيل البنود وقياس الالتزام

بعد ملاحظات الاستخدام على مخرجات PDF ومتابعة المهام، عولجت الآتي — وكلها **بأثر رجعي**
على المحاضر السابقة، لأن صفحة المحضر تُولَّد من قاعدة البيانات عند كل طلب:

- **لا تراكم بين النص والترويسة:** كان الحشو العلوي يسري على الصفحة الأولى وحدها فتنزلق نصوص
  الصفحات التالية فوق الترويسة الثابتة. صار المحتوى داخل **جدول إطار** بصفَّي حجز (`thead`/`tfoot`)
  يحجزان ارتفاع الترويسة والتذييل في **كل** صفحة، والإطار مثبَّت العرض فلا يطفح جدول عريض خارج الهوامش.
  (ترقيم الصفحات لا يعمل عبر `counter(page)` خارج صناديق `@page` في Chrome وFirefox — فحلّ محلَّه
  رقم المحضر في تذييل كل صفحة، ومن أراد ترقيمًا فعّل «الترويسة والتذييل» في نافذة الطباعة.)
- **تمييز وتلوين:** شارات ملوّنة للحالة والنوع والأولوية والتأخير، وتظليل صفوف المتعثّر والمنجَز،
  وترويسة جدول بلون الهوية، وأشرطة نسبة إنجاز داخل الخلايا، مع `print-color-adjust: exact`
  حتى تُطبع الألوان كما تُعرض (فهي دلالة لا زينة).
- **لوحة مؤشرات وتمثيل بصري:** في رأس كل محضر بطاقات مؤشرات (الحضور، التواقيع، البنود الجديدة،
  المُرحَّلة، المتأخرة، أيام التأخير) مع **حلقة توزيع الحضور** وأشرطة حالات البنود ومقاييس نسبية —
  كلها SVG مضمَّن بلا مكتبات خارجية. وبطاقة تقرير الطالب أخذت لوحتها المصغّرة أيضًا.
- **عمود المسؤول:** ظهر في جدول القرارات والتوصيات والمهام وفي جدول المتابعة، طباعةً وواجهةً.

**ترحيل بنود المتابعة (§٤٫٣):** البند غير المنجَز يُرحَّل إلى المحضر التالي ثم الذي يليه حتى يُنجَز،
وحين يُنجَز يظهر **مرة أخيرة واحدة** للتوثيق ثم لا يظهر بعدها. يُسجَّل ذلك في جدول
`meeting_followups`: يُحسب حيًّا للمحضر المفتوح، ويُجمَّد عند الاعتماد فلا يتبدّل محضر مقفل بتغيّر
حالة البنود بعده، وتُعاد بناء لقطات المحاضر المعتمدة القديمة تلقائيًا عند الإقلاع (أثر رجعي).
كل ترحيل يرفع عدّاد `carried_count` على البند نفسه — وهو مؤشر التعثّر.

**قياس التأخير والالتزام:** يُسجَّل على البند `delay_days` (الإنجاز ناقص الاستحقاق بالأيام: موجب = تأخير)
لحظة الإنجاز أو تعديل تاريخه، ويبقى `first_due_date` مرجعًا للوعد الأصلي فأي تمديد يظل مرئيًا.
ومنه لوحة **«الالتزام والأداء»** في شاشة المهام: نسبة الإنجاز، دقة التوقيت، المتأخرة الآن والمتعثرة،
مجموع أيام التأخير ومتوسطها وأطولها، ومرات الترحيل — لكل مكلَّف، مع «أكثر البنود تعثّرًا».
ونسبة الالتزام = ٦٠٪ إنجاز + ٤٠٪ دقة توقيت، وتظهر أيضًا **بجانب نتائج التقييم** في لوحة المشرفين
وأعضاء الفرق لتكون جزءًا من صورة تقييم المكلَّف، وملخّصها في الصفحة الرئيسية لكل مستخدم.

### تصفّح الجوال وتطبيق الشاشة الرئيسية

المنصة تُستعمل من الجوال أكثر مما تُستعمل من المكتب، فأُعيد ضبط الواجهة على مقاس الهاتف:

- **لا تمرير أفقي في أي شاشة.** الجداول العريضة (المتابعة، القرارات، الالتزام، المستخدمون…)
  تتحوّل تلقائيًا إلى **بطاقات**: كل صف بطاقة، وكل خلية سطر «العنوان: القيمة». يتم ذلك بنسخ
  عنوان العمود إلى الخلية عند العرض، فيسري على كل جدول في المنصة — والجديد منها كذلك — بلا
  تعديل في كل شاشة على حدة.
- **تنقّل بإبهام واحد:** شريط تبويب سفلي (الرئيسية · المحاضر · المهام · التقييم · المزيد)،
  وقائمة جانبية تنزلق من اليمين فوق ستارة معتمة وتُغلق باللمس خارجها أو باختيار وجهة،
  وشريط علوي مضغوط ينقل أزرار الحساب إلى القائمة ويفتح البحث الشامل كورقة بعرض الشاشة.
  > **مزلق وثّقناه في الملف:** `inset-inline-*` منطقية تنقلب مع اتجاه المستند بينما
  > `translateX` فيزيائية لا تنقلب. خلطُهما أرسى الدرج على الحافة المعاكسة وأزاحه إلى
  > داخل الشاشة بدل خارجها، فبقي شريط منه ظاهرًا يبتلع اللمسات ويفتح شاشات لم تُطلَب.
  > الإرساء الآن منطقي واتجاه الإخفاء يتبع اتجاه المستند عبر متغيّر، والعناصر العائمة
  > أسفل الشريط العلوي تتبع ارتفاعه الفعلي لا رقمًا ثابتًا.
- **مقاسات لمس وإدخال سليمة:** أهداف لمس لا تقل عن ٤٢ بكسل، وحقول بحجم ١٦ بكسل فأعلى
  (وإلا كبّر آيفون الصفحة تلقائيًا عند التركيز)، والنوافذ المنبثقة تصبح **أوراقًا سفلية**
  بأزرار ممتدة، مع احترام مناطق الأمان (`env(safe-area-inset-*)`) في الشقّ وشريط الإيماءة.
- **تصدير المحضر من الجوال:** صفحة الطباعة صارت تُقرأ على شاشة الهاتف (هوامش مضغوطة،
  بطاقات مؤشرات بعمودين، وجداول تُمرَّر داخل حاويتها وحدها)، وفي أسفلها شريط ثابت فيه
  **«طباعة / حفظ PDF»** و**«مشاركة الرابط»** (عبر مشاركة النظام)، مع إرشاد لمستخدم آيفون
  إلى الحفظ في «الملفات». مخرجات الورق A4 لم تتغيّر بشيء من هذا.
- **تطبيق شاشة رئيسية للآيفون:** `viewport-fit=cover` وأيقونة `apple-touch-icon`،
  و**شاشات إقلاع** مولّدة لتسعة مقاسات آيفون (بلا وميض أبيض عند الفتح)، وبطاقة دعوة للتثبيت
  تظهر مرة واحدة وتشرح خطوات «المشاركة ← إضافة إلى الشاشة الرئيسية» على iOS وتُثبِّت بضغطة
  على أندرويد، ووضع مستقل مُكتشَف يضبط الهوامش العلوية.
- **متانة العمل دون اتصال:** عامل الخدمة صار يخزّن كل أصل على حدة (فشل واحد لا يُسقط
  التخزين كله)، وله **مهلة شبكة** يرجع بعدها إلى النسخة المخزَّنة بدل ترك الصفحة معلّقة،
  ولا يُرجع هيكل HTML مكان ملف سكربت (كان يكسر الصفحة بصمت)، ويُفعّل النسخة الجديدة
  ويُحدّث الصفحة تلقائيًا عند نزول تحديث.
- **الخط لا يحجب الإقلاع:** ورقة نمط الخط الخارجية كانت تُوقف تنفيذ السكربتات بعدها، فتبقى
  الشاشة فارغة كلما تعذّر الوصول إلى خدمة الخطوط (شبكة جوال ضعيفة أو مقيّدة). صارت تُحمَّل
  بلا حجب مع خط احتياطي فوري.

### إشعارات الدفع (جوال + تطبيق الشاشة الرئيسية)

كانت الإشعارات تصل داخل المنصة فقط (جرس يُقرأ عند فتح الموقع) وبريدًا اختياريًا. أُضيفت
قناة ثالثة: **إشعار على الجهاز يصل والتطبيق مغلق**، بتنفيذ كامل داخل الـ Worker:

- **المعياران:** VAPID (RFC 8292) برمز JWT موقَّع بـ ES256، وتعمية الحمولة
  aes128gcm (RFC 8291) بمفتاح مؤقّت لكل رسالة عبر ECDH مع مفتاح المتصفح وسرّ الاشتراك.
  نُعمّي الحمولة ولا نكتفي برسالة فارغة، فسفاري على آيفون لا يضمن تسليم الدفع بلا حمولة.
- **بلا إعداد يدوي:** يُولَّد زوج مفاتيح VAPID عند أول طلب ويُحفظ، ويمكن تثبيته كأسرار
  بيئة (`VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT`) وهو المستحسن للإنتاج.
- **كل إشعارات المنصة تُدفع:** الدعوة، وبانتظار التوقيع، والاعتماد، وإسناد المهام،
  وتذكيرات الاستحقاق والتأخّر اليومية، وفتح دورة التقييم ونشر النتائج — القناة مربوطة
  في `notify`/`notifyMany` فلا حاجة لتعديل كل مُطلِق إشعار.
- **آيفون:** iOS لا يمنح إذن الإشعارات لصفحة في سفاري، بل للتطبيق المضاف إلى الشاشة
  الرئيسية وحده (iOS 16.4+). فتعرض المنصة لمستخدم آيفون خطوات التثبيت بدل زر لا يعمل،
  وبعد التثبيت تظهر دعوة لتفعيل الإشعارات مرة واحدة.
- **إدارة الأجهزة:** شاشة الإشعارات فيها بطاقة «إشعارات الأجهزة»: الحالة، وتفعيل/إيقاف
  هذا الجهاز، و**إشعار تجريبي**، وقائمة الأجهزة المسجَّلة (نوعها، ومتى سُجِّلت، ومتى وصلها
  آخر إشعار). حدّ عشرة أجهزة لكل مستخدم، والاشتراك الباطل (404/410) يُحذف تلقائيًا،
  والمتكرّر الإخفاق يُسقط بعد عشر محاولات.
- **تفاصيل تُحسِّن التجربة:** الإشعار عربي RTL بأيقونة المنصة، ووسم لكل نوع فلا تتراكم
  عشرات النسخ، والنقر عليه يُركّز نافذة مفتوحة وينقلها للرابط بدل فتح نسخة ثانية،
  وعدد غير المقروء يظهر **شارةً على أيقونة التطبيق** في الشاشة الرئيسية، وتدوير مفاتيح
  الاشتراك (`pushsubscriptionchange`) يُعاد تسجيله بصمت.

تحقّقنا من السلسلة كاملة محليًا: فكّ تعمية الحمولة والتحقق من توقيع VAPID بمفتاح
«متصفح» وهمي، ثم إرسال فعلي من الخادم إلى خدمة دفع محلية عند إسناد مهمة وعند تحويل
محضر للتوقيعات، وتسليم رسالة دفع اصطناعية لعامل الخدمة في متصفح حقيقي والتأكد من
ظهور الإشعار بمحتواه ورابطه.

### تمييز الأشخاص بلون ثابت، وجداول تصدير بلا تراكم

- **لون لكل شخص، ثابت في كل المحاضر وكل المجالس.** كان اسم المسؤول يُطبع سردًا
  (`اسم، اسم، اسم`) فيصعب تمييز صاحب المهمة حين يتعدّد المسؤولون. صار لكل مستخدم لون
  محفوظ عليه (`users.color`) يُعرض **شارةً بإطار منحني وخلفية فاتحة من لونه**، في صفحة
  الطباعة وجداول المحضر والمهام ولوحة الالتزام وجدول المستخدمين. اللون يُقرأ من المستخدم
  ولا يُنسخ في البنود، فتغييره يسري فورًا **بأثر رجعي** على كل المحاضر السابقة.
- **قابل للتعديل من إعدادات المستخدمين:** منتقي ألوان في نموذج المستخدم بمعاينة حيّة
  للشارة كما ستظهر في المحضر، وتعليم الألوان المستعملة لغير هذا المستخدم حتى لا يتكرّر
  لونان سهوًا. اللون يُتحقَّق منه في الخادم (`#RRGGBB`)، ومن لم يُختَر له لون يأخذ لونًا
  افتراضيًا ثابتًا مشتقًّا من معرّفه — والمستخدمون القدامى يُعبَّأون مرة واحدة عند الإقلاع.
  ولوحة الألوان بعيدة عمدًا عن ألوان الحالة (أخضر منجَز · ذهبي جارٍ · أحمر متأخر) حتى لا
  يختلط لون الشخص بلون حالة البند.
- **لا تراكم للنصوص داخل جداول PDF.** كان `white-space: nowrap` على رقم البند والتاريخ،
  وشريط الإنجاز المصفوف أفقيًا مع رقمه، يتجاوز عرض عموده في تخطيط `table-layout: fixed`
  — والفائض في الجدول لا يُقصّ بل **يعلو نص الخلية المجاورة**. المعالجة من الجذر:
  عرض الأعمدة أُعيد توزيعه على حاجة المحتوى الفعلي، وشريط الإنجاز صار مكدَّسًا (الرقم
  فوق الشريط) فيتبع عرض عموده مهما ضاق، والأرقام والرموز تنكسر سطرين بدل أن تتسرّب،
  والطابع الزمني صار تاريخًا وسطرًا تحته ساعة. وأُضيف `overflow: hidden` على خلايا
  الجداول المثبَّتة **حاجزًا أخيرًا** لا حلًّا: التوزيع الجديد يجعله لا يُشتغل أصلًا.
  > **قِسنا الأمر ولم نقدّره:** فحص آليّ يقرأ صناديق كل مقطع نصّي في ملف PDF المولَّد
  > ويقارنها بخطوط الجدول الرأسية — أي مقطع يعبر خطًّا فهو تسرّب، وأي «…» فهو قصّ يضيّع
  > معلومة. الفحص كان يرصد ستّ حالات تسرّب، وهو الآن صفر تسرّب وصفر قصّ على بيانات ضغط
  > (أسماء طويلة، أربعة مسؤولين للبند، تأخير بثلاثة أرقام).
- **الشارة على الجرس داخل الإطار:** عدد الإشعارات غير المقروءة كان يخرج من حافة الشاشة
  على الجوال لأن مرجعه في التموضع صار الشريط العلوي لا زرّ الجرس نفسه. صار الزرّ هو
  مرجع الشارة، فتلتصق به على كل عرض ومهما بلغ العدد. وأُضيف فحص دوري يتحقق أن **كل**
  عنصر مُتموضِع مرجعه والده المباشر، وأن لا شيء ثابتًا داخل سلف محوَّل (`transform`)،
  وأن كل الطبقات العائمة داخل الإطار — على أربعة أعراض شاشة وثلاث حالات فتح.
- **الجداول الكثيفة تُقرأ على المكتب أيضًا:** جدول بعشرة أعمدة كان يُعصر داخل البطاقة
  حتى تصير كل خلية كلمة في كل سطر. صار له غلاف بتمرير أفقي وحدّ أدنى للعرض على الشاشات
  الواسعة — وعلى الجوال يبقى مُكدَّسًا بطاقاتٍ كما هو.

### الحالة الفعلية للبند، وترتيب صفحات المحضر

**«متعثّرة» واقعة لا حالة تُكتب.** كان البند الذي مضى استحقاقه ولم يُنجَز يُعرض بحالته
المسجَّلة («لم تبدأ») في المحضر وفي الموقع معًا، فيقرأ القارئ خلاف الحقيقة وتضيع دلالة
التعثّر. صارت الحالة **تُشتقّ عند العرض ولا تُكتب على البند**: ما لم يُنجَز ومضى استحقاقه
متعثّر. والاشتقاق لا يبطل ما سجّله المسؤول (نسبته وتقدّمه كما هي)، ولا يتقادم (تمديد
الاستحقاق يُعيد البند لحالته فورًا بلا ترحيل بيانات)، ويسري **بأثر رجعي** على كل المحاضر
المعتمدة لأنه يُحسب من اللقطة المجمَّدة لا يُخزَّن فيها.

والمرجع الزمني يتبع السياق: **تاريخ انعقاد المحضر** داخل المحضر — فالوثيقة تصف حال ذلك
اليوم ولا تتبدّل بعده، ومسودة محضر مقبل لا تُقدّم تأخيرًا لم يقع بعد (المرجع لا يتجاوز
اليوم) — و**اليوم** في شاشة المهام ولوحة الالتزام. ولذلك يظهر البند نفسه «متأخرة ٩٩ يومًا»
في محضر قديم و«متأخرة ٢٠١ يومًا» في شاشة المتابعة: كلاهما صحيح في موضعه. وتبقى الحالة
المسجَّلة `stalled` متاحة يدويًا لبند متعثّر بلا استحقاق فائت (معطَّل بانتظار غيره).
وبعد الاشتقاق صار عمودا «متأخرة الآن» و«متعثرة» في لوحة الالتزام بمعنى واحد فدُمِجا.
كما كانت بطاقة «أيام التأخير» تعدّ تأخّر المنجَز وحده فتقول «لا تأخير» بجوار «٣ متأخرة» —
صارت تجمع ما تراكم على المفتوح وما تأخّره المنجَز، مع تفصيلهما تحتها.

**المحضر يُقرأ قسمًا قسمًا.** كان يُطبع سيلًا متصلًا فيقع عنوان جدول في ذيل صفحة وبياناته
في التالية. صار لكل قسم صفحته: الصفحة الأولى للتعريف ولوحة المؤشرات والحضور، ثم جدول
الأعمال، ثم متابعة بنود المحاضر السابقة، ثم القرارات والتوصيات والمهام، ثم التوقيعات ورمز
التحقق — كلٌّ يبدأ من رأس صفحة ويمتدّ إلى ما يحتاجه، ورأس الجدول يتكرّر على كل صفحة
يمتدّ إليها، والعنوان ملازم لجدوله (`break-after: avoid`).

**مقاسات الخط أُعيدت معايرتها** على عرض A4 الفعلي (١٨٢ مم): المتن ١١٫٥ والجداول ١١
وعناوين الأعمدة ١٠٫٥ والشارات ٩٫٥ — تصغير محسوب يوسّع الأعمدة فتتنفّس الكلمات، لا تصغيرًا
يُتعب العين. وعنوان العمود لم يعد يُقصّ في منتصف الكلمة.
> **قِسنا الأمر ولم نقدّره:** فحص يمرّ على كل كلمة في الصفحة ويطلب مستطيلاتها
> (`Range.getClientRects`) في وسط الطباعة بعرض المساحة المطبوعة الحقيقي — أكثر من مستطيل
> يعني كلمة انكسرت في منتصفها. الفحص يرصد الانكسار فعلًا (جرّبناه على عرض ضيّق فأخرج
> «الاستحقاق» و«الإنجاز» و«م/تربوي/٠٠١»)، وعلى عرض A4 لا يرصد شيئًا.

### الترويسة صفّ جدول لا عنصر ثابت، وأعمدة تحتمل خطًّا أعرض

تصدير حقيقي من متصفح المستخدم كشف ثلاثة أعطال لم يُظهرها كروم:

- **الترويسة تحجب المحتوى.** كانت الترويسة والتذييل عنصرين `position: fixed` يُفترض أن
  يتكرّرا على كل صفحة. كروم يفعل، وسفاري يرسمهما **مرة واحدة** فتهبط الترويسة في وسط
  الصفحة الثانية فوق جدول الحضور فتحجب صفوفًا منه، وتغيب عن الصفحة الأولى مع بقاء مكانها
  محجوزًا فارغًا — فبدأت الصفحة بعد ربعها ودُفع «الحضور» إلى صفحة إضافية. صارت الترويسة
  صفّ `thead` والتذييل صفّ `tfoot` في جدول الإطار: تتكرّر بآلية الجداول التي تحترمها كل
  المتصفحات، وتحجز مكانها حقًّا فيستحيل أن تحجب محتوى.
- **حروف مقصوصة في الأعمدة.** الأعمدة كانت معايَرة على مقاسات خط Tajawal وحده؛ فإن لم
  يصل خط الويب (طباعة بلا شبكة) سقط المتصفح إلى خط نظام أعرض بنحو الربع، فضاقت الأعمدة
  وانكسرت «الاستحقاق» و«الإنجاز» و«مهمة» في منتصفها ثم قُصَّت. عولج من وجهين: قاعدة منع
  الكسر داخل الكلمة كانت تُغلَب لأن قاعدة عامة تليها في الملف بالأولوية نفسها — نُقلت
  بعدها؛ وعروض الأعمدة أُعيد توزيعها بهامش أمان يحتمل خطًّا أعرض بنحو الثلث.
- **الصفحة الأولى قسم واحد.** بطاقات المؤشرات الستّ كانت تلتفّ إلى سطرين فتدفع «الحضور»
  إلى الصفحة التالية — صارت في صفّ واحد على الورق (وتلتفّ على الجوال حيث لا مجال)، مع
  ضغط الهوامش والترويسة، فصار التعريف ولوحة المؤشرات والحضور في صفحة واحدة لمجلس حتى
  أربعة عشر عضوًا.

ومعها: عمود «النص» صار **«البند»** في كل الجداول طباعةً وواجهةً، ولكل قسم **علامة انتهاء**
(خطّان متلاشيان ومعيّن صغير) في سطر واحد لا يزيد صفحة.

> **قِسنا القصّ أيضًا:** فحص يقارن، لكل خلية، عرض محتواها بعرضها الداخلي وموضع كل عنصر
> بداخلها بحدود الخلية — أي تجاوز يعني حرفًا مخفيًّا. يُشغَّل مرتين: بخط الهوية، وبخط
> أعرض منه بنحو الربع يحاكي سقوط خط الويب. صفر قصّ في الحالتين.

تصديرٌ ثانٍ من المتصفح نفسه أظهر بقيّتين، فعولجتا:

- **صفحة كاملة فارغة.** فاصل نهاية القسم كان عنصرًا مستقلًّا، فدُفع وحده إلى صفحة جديدة
  فبدت فارغة (لا يحمل نصًّا). صار الفاصل **حدًّا سفليًّا على صندوق القسم نفسه**: زخرفة
  الصندوق تُرسم مع آخر جزء منه ولا تُولّد صفحة أبدًا — والحدّ متدرّج التلاشي بلون الهوية
  فيؤدّي الغرض البصري نفسه.
- **الترويسة لا تتكرّر، وسطرٌ يتيم يهدر صفحة.** كان جسم الإطار خلية واحدة عملاقة، وبعض
  المحركات لا تكرّر صفّ الترويسة فوق خلية ممتدّة. صار **كل قسم صفًّا مستقلًّا** في جدول
  الإطار — وهي البنية التي تُبنى عليها آلية تكرار رؤوس الجداول أصلًا. ومعها استُرجع نحو
  ٧٥ بكسل من الصفحة الأولى (عمود عناوين البيانات أوسع فلا يلتفّ «التاريخ الميلادي»، وحلقة
  الحضور أصغر، وهوامش العناوين والبطاقات أضيق)، فصار قسم الصفحة الأولى يسع **حتى خمسة
  عشر عضوًا** بدل أربعة.

> وأُضيف للفحص شرطٌ ثالث: **صفحة بلا محتوى** — أي صفحة لا تحمل غير الترويسة والتذييل.
> صفر في المحضر المفرد وفي الحزمة (خمس عشرة صفحة) وفي تقرير الطالب.

**خطأ ارتكبناه وتراجعنا عنه — يُوثَّق لئلّا يتكرّر.** مع إصلاح الصفحة الفارغة حوّلنا كل قسم
من عنصر كتليّ (`div`) إلى صفٍّ في جدول الإطار (`tr`)، طمعًا في أن يكرّر المحرّك صفّ الترويسة
على كل صفحة. الأدوات هنا تشغّل كروم وحده، وكروم يحترم قطع الصفحة قبل الصفّ فمرّ الاختبار —
بينما محرّك المستخدم يتجاهلها، **فالتحمت الأقسام كلها** وعاد ما كان قد صحّ. أُعيد القسم عنصرًا
كتليًّا، وبقي ما ثبتت صحّته في متصفح المستخدم نفسه (الترويسة في `thead` بلا حجب، والفاصل حدًّا
على صندوق القسم). والقاعدة المستفادة صريحة: **لا يُستبدل بناءٌ ثبتت صحّته في متصفح المستخدم
ببناءٍ لا نملك التحقّق منه** مهما بدت الفائدة — وتكرار الترويسة على كل صفحة ليس ثمنه تقسيم
المحضر.

### المكان، ومقياس التأخير، وتحويل البند إلى مهام

- **مكان الاجتماع لا يضيع.** كانت خانة «المكان» في المحضر تخرج بنوعها وحده («حضوري») بلا
  اسم المكان، **والمكان مكتوبٌ فعلًا لكن في خانة «عنوان الاجتماع»** فيظهر تحت رقم المحضر بلا
  عنوان يدلّ عليه. مسارات الحفظ كلها سليمة (تحقّقنا منها بقيادة الواجهة فعلًا)، والعطب في
  النموذج نفسه: أول حقل نصّ حرّ يقابل المستخدم هو «العنوان»، والمكان مدفون بعده بصفَّين.
  عولج من ثلاث جهات: حقل المكان انتقل بجوار العنوان مباشرة وصار **مطلوبًا**، وكلاهما يحمل
  توضيحًا يفصل بينهما («موضوع الاجتماع أو تسميته — وليس مكانه»)، **والإرسال للتوقيعات يُوقَف**
  إن كان المكان فارغًا — فهي آخر لحظة يُستدرك فيها قبل أن تُقفل الترويسة. وأُصلح معها عطب
  حقيقي: محضر التصويب/الملحق كان **يُسقط المكان والوقت والعام الدراسي** من المحضر الأصل.
  وفي المحضر يُكتب اسم المكان أولًا والنوع شارةً بجانبه، وإن غاب المكان كُتب «لم يُذكر المكان»
  صراحةً بدل السكوت عنه.
- **التأخير يُقاس بأطول مدّة لا بمجموع الأيام.** بندان تأخّر كلٌّ منهما خمسة أيام ليسا تأخيرًا
  مقداره عشرة؛ الجمع يضخّم الرقم بلا معنى. صارت البطاقة «أطول تأخير» في المحضر وفي لوحة
  الالتزام وفي الصفحة الرئيسية، وعمود «مجموع أيام التأخير» صار «أطول تأخير» — والمتوسط باقٍ
  فهو مقياس ذو معنى.
- **«إلى مهمة» صار يقرأ البند كاملًا.** كان ينسخ **عنوان** البند حرفيًّا إلى نص المهمة،
  والعنوان لا يحمل ما نوقش. صار المساعد يقرأ البند بعنوانه ونصّ مناقشته (مجرَّدًا من الوسوم)
  فيصوغ ما يترتّب عليه: مهمة واحدة إن كفت، وأكثر إن اقتضى البند — بحدّ ستّة، ولا يفتعل ما لم
  يقتضه، ولا ينسب مسؤولًا ولا يخترع تاريخًا. ولكل مقترح **نصّه ونوعه وأولويته وموعده
  ومسؤولوه** قابلة للتعديل قبل الإضافة، ويُقترح موعد مبدئي من تقدير النموذج. وعند تعطيل
  المساعد يفتح النموذج اليدويّ مهيّأً بالعنوان **ونصّ البند** لا بالعنوان وحده.
- وأُصلحت «هـ» مكرّرة في التاريخ الهجري: `Intl` يُلحقها بنفسه في التقويم الهجري، وكنّا نُلحقها
  ثانيةً فتُكتب «١٤٤٨ هـهـ».

> **ما تحقّقنا منه وما لم نستطع:** قُدنا المسار كاملًا في متصفح حقيقي — فتح الحوار من بند
> فيه محتوى غنيّ، وتعديل النص والموعد وإسناد مسؤول، والحفظ — ثم تأكّدنا من القاعدة أن البند
> حُفظ بنصّه المعدَّل وموعده ومسؤوله، وأن غير المحدَّد لم يُحفظ. أما صياغة النموذج نفسها فلا
> تعمل محليًّا (Workers AI يطلب حساب Cloudflare)، فاستُبدلت بردٍّ مُعدّ في الاختبار.

> **وحرسناه بفحص:** تدقيق بنيويّ يقرأ ملف PDF المخرَج ويتأكّد أن **كل قسم يفتتح صفحة**
> بترتيبه ومرة واحدة داخل كل محضر، وأن لا صفحة بلا محتوى (مع تجاهل شريطَي هامش المتصفح
> اللذين يطبع فيهما تاريخه ورابطه). ولأن استخراج العربية من PDF يعكس ترتيب الكلمات وقد
> يخلط حروف الكلمة، تُقارَن العناوين بـ«بصمة حروفها». والفحص مُعاير على الواقع: يرسب على
> ملف المستخدم الملتحم (أربع ملاحظات) وعلى الملف الذي فيه صفحتان مهدرتان، وينجح على
> المخرَج بعد الإصلاح — مفردًا وحزمةً وتقريرَ طالب.

## نموذج الاطلاع ودورة حياة المستخدم

### القاعدة الواحدة

> **ترى السجل إن أُنشئ أثناء فترة كنت تملك فيها الاطلاع على مجلسه.**

فلا أرشيف يسبق انضمامك، ولا ينقطع عنك ما كنت تراه بعد انتقالك. كل تغيير للدور أو المرحلة
يُقفل الفترة الجارية ويفتح فترة جديدة في `user_role_periods`، فتتكوّن **نوافذ اطلاع**
نصف مفتوحة `[من، إلى)` لا تتداخل، وينتمي كل سجل إلى فترة واحدة بالضبط.

**الميزان وقت إنشاء السجل (`created_at`) لا تاريخ انعقاد الاجتماع:** العبرة بما كان موجودًا
في المنصة أثناء خدمته، فمحضر يُدوَّن بعد انتقاله عن جلسة قديمة محجوب عنه — إلا أن يكون حاضرًا فيه.

ويُستثنى من القاعدة استثناءان مقصودان:

| الاستثناء | لماذا |
|---|---|
| **السجل الشخصي** — من حضر محضرًا أو أُسند إليه بند يراه أبدًا مهما تغيّر دوره | لا يُحجب عن أحد ما شارك فيه أو وقّعه |
| **العمل الجاري** — المحضر غير المعتمد والبند المفتوح يراهما صاحب الاطلاع الكامل الحالي ولو أُنشئا قبل انضمامه | وإلا تجمّدت محاضر السلف المعلّقة ولم يعتمدها الخلف |

وتبقى **درجة الاطلاع** (`full` / `legacy` / `none`) مشتقّة من الدور والمرحلة الحاليّين وحدهما،
وهي التي تحكم **صلاحيات الكتابة**: التحرير والاعتماد والتعليق للاطلاع الكامل فقط، وما دونه قراءة.

### تغيير الدور أو المرحلة (مثال: مشرف متوسط ← عضو فريق ثانوي)

| البند | الأثر |
|---|---|
| **مرحلته السابقة (المتوسطة)** | اطلاع **قراءة فقط** على ما أُنشئ فيها أثناء خدمته. لا تحرير ولا اعتماد ولا تعليق، ولا يرى شيئًا استُجدّ فيها بعد الانتقال. |
| **مرحلته الجديدة (الثانوية)** | اطلاع **كامل** على ما يُنشأ فيها **من تاريخ انضمامه**، ولا يُفتح له أرشيفها السابق. ويرى محاضرها غير المعتمدة وبنودها المفتوحة ولو سبقته (استثناء العمل الجاري). |
| **المجلس التربوي** | يُفقد الاطلاع الكامل عند نزوله عن المشرف الأول، ويبقى الاطلاع التاريخي على ما سبق. |
| **العضوية** | تُزال آليًا من مجالس المرحلة السابقة، وتُضاف لمجلس المرحلة الجديدة (رئيسًا إن كان مشرفًا أول وليس للمجلس رئيس، وإلا عضوًا). |
| **الرئاسة** | إن كان رئيس مجلس سيفقده: **مانع** حتى يُحدَّد من يخلفه. |
| **الكتابة** | يُلغى تعيينه كاتبًا افتراضيًا للمجالس المفقودة، وتُفرَّغ خانة الكاتب في محاضرها غير المعتمدة (المعتمدة تحتفظ باسمه في السجل). |
| **مهامه المفتوحة** | تبقى مسندة إليه ويستطيع متابعتها وإنجازها بقاعدة السجل الشخصي. |
| **تواقيعه المعلّقة** | يبقى قادرًا على التوقيع لأنه مسجَّل في الحضور. |
| **فراغ الاعتماد** | إن كانت مرحلته ستبقى بلا مشرف أول ولديها محاضر غير معتمدة: **مانع** (لا معتمد لها). |
| **التقييم** | تتغيّر قائمة من يقيّمهم ومن يقيّمونه فورًا، وتبقى مدخلاته السابقة مسجّلة كما هي. |
| **الجلسات** | تُنهى جلساته المفتوحة ليُعاد تحميل صلاحياته من جديد. |

### تعليق مستخدم

يمنع الدخول فورًا وينهي الجلسات، **ولا يمسّ شيئًا من ارتباطاته** — يستعيدها كاملة عند رفع التعليق.

- **المهام:** تبقى مسندة إليه ويتوقف تقدّمها. تُستبعد إشعاراته وتذكيراته، ويُنبَّه رئيس مجلسه بأن البند بلا مسؤول فعّال. ويمكن نقل بنوده المفتوحة إلى غيره عند التعليق.
- **المحاضر:** يظل مسجَّلًا في حضور المحاضر السابقة. أي محضر **بانتظار توقيعه** لن يُعتمد ما دام معلّقًا — لذلك يُعرض ذلك **كمانع** يستوجب تجاوز التوقيع من الرئيس بسبب مسجَّل، أو تأكيدًا صريحًا. ولا يُدرَج في حضور المحاضر الجديدة ما دام معلّقًا.
- **التقييم:** يُستبعد كمقيِّم وكمُقيَّم من الدورات المفتوحة، ومن مرشّحي التفويض.

### حذف مستخدم

على مستويين، بحسب أثره في السجلات:

**١) الحذف الأرشيفي (الافتراضي)** — للمستخدم المرتبط بمهام ومحاضر:

- يُمنع الدخول نهائيًا ويختفي من كل القوائم والاختيارات.
- **كل سجل رسمي يبقى باسمه ولا يُمسّ:** المحاضر التي أنشأها أو كتبها أو اعتمدها، حضوره وتواقيعه ورموز تحققها، تقييماته المُسلَّمة، مرفقاته وتعليقاته، وقيوده في سجل التدقيق. المحضر المعتمد وثيقة موقّعة لا تُغيَّر بحذف حساب.
- تُزال عضوياته وإشعاراته وجلساته، ويُلغى تعيينه كاتبًا افتراضيًا، وتُفرَّغ خانة الكاتب في المحاضر غير المعتمدة.
- **بنوده المفتوحة** تُنقل إلى بديل يُحدَّد. وإن وُجد بند لا مسؤول عنه غيره ولم يُحدَّد بديل فهو **مانع**.
- **رئاسة مجلس** بلا خلف: **مانع**. **توقيع معلّق** على محضر: **مانع** (يستوجب تجاوز الرئيس بسبب مسجَّل).
- **يُحرَّر بريده** ليصبح قابلًا لإنشاء حساب جديد به، ويُحفظ الأصلي في `deleted_email`.
- **قابل للاستعادة:** يعود الحساب في وضع «معلَّق» بانتظار مراجعة دوره، والعضويات تُعاد يدويًا.

**٢) الحذف النهائي** — لا يُتاح إلا لمن **لا أثر له إطلاقًا** في السجلات (لم يحضر محضرًا ولم يوقّع ولم يُسند إليه بند ولم يقيّم)، وبعد الحذف الأرشيفي. يُزال صفّه من قاعدة البيانات، وتُفصل قيود تدقيقه عن الحساب مع حفظ لقطة باسمه وبريده ودوره في قيد الحذف.

### ضمانات عامة

- **تقرير أثر قبل كل عملية:** `GET /api/users/:id/impact?action=…` يُرجع ما سيحدث، والموانع، والتحذيرات، وجدول الاطلاع على المجالس قبل/بعد بعدد المحاضر المرئية، والسجلات التي ستبقى محفوظة. والواجهة تعرضه قبل التنفيذ.
- **الموانع توقف التنفيذ** (409) ولا تُتجاوز إلا بتأكيد صريح يُسجَّل في سجل التدقيق.
- **لا يمكن للمسؤول تنفيذ العملية على حسابه**، ولا حذف/تعليق آخر رئيس نشط أو آخر مدير نظام.
- **الكتابة تتطلب اطلاعًا كاملًا حاليًا:** من انتقل عن مرحلة لا يحرّر محاضرها ولو بقي مسجَّلًا ككاتب لها.
- **قاعدة «المُقيَّم لا يرى نتيجته»** مضمونة باستبعاد المستخدم من قوائم نتائج فئته، فلا تنكشف عليه نتيجته لو تغيّر دوره.

2. **إنشاء دورات التقييم للرئيس حصراً** (افتراض الوثيقة).
3. **تجاوز التوقيع للرئيس** متاح مع تسجيل السبب في التدقيق (افتراض الوثيقة).
4. **جهة الاعتماد الوحيدة (محسومة):** محضر المجلس التربوي يعتمده **الرئيس** فقط، ومحضر مجلس
   كل مرحلة يعتمده **مشرفها الأول** فقط — الرئيس لا يعتمد محاضر المراحل. (الرئيس يحتفظ بصلاحية
   الاطلاع والإنشاء على كل المجالس، لكن الاعتماد حصري لكل مجلس بجهته.)
